# ADR-0001 — Технологический стек OmniProxy

- Статус: proposed
- Дата: 2026-08-27
- Контекст: §2.1 промта задаёт стек, но требует обоснования каждой зависимости и
  явного выбора слоя TLS-имперсонации.

## Решение

### Язык и сборка
| Выбор | Обоснование | Отвергнуто |
|---|---|---|
| TypeScript strict, ESM, Node ≥ 22 | Zod-схемы дают типы бесплатно; strict нужен, потому что данные приходят из недоверенного upstream | Оставить JS — потеря контракта между 15 пакетами |
| pnpm workspaces + Turborepo | Дешёвый кэш задач, строгий `node_modules` ловит незадекларированные импорты (важно для правила «адаптер не трогает ядро») | npm workspaces — нет кэша; Nx — избыточен |
| tsup (esbuild) на пакет | Быстро, без плагинного зоопарка | tsc-only — медленно; Rollup — лишняя конфигурация |

### HTTP-сервер
**Fastify 5.** Schema-first совпадает с решением «Zod — единственный источник истины»
(`fastify-type-provider-zod` даёт валидацию входа и генерацию `/openapi.json` из тех же
схем). SSE пишем вручную через `reply.raw` — переносим существующие эмиттеры из
`server.js:1386-1530`, они уже корректны и покрыты тестами; плагины SSE не берём,
они мешают контролировать heartbeat и backpressure.
Отвергнуто: Hono (слабее экосистема валидации/OpenAPI под Node), голый `node:http`
(сегодня работает, но 4 диалекта × мультиарендность × job-API — это роутер, который
придётся написать самому).

### Upstream-транспорт — критический путь (§6.1)
Три уровня за одним интерфейсом `HttpClient`:

1. **`undici`** — базовый уровень. Ручной контроль заголовков и их порядка, HTTP/2,
   пулы, `AbortSignal`. Для классов B и F этого достаточно.
2. **`tls-client` (bogdanfinn) как sidecar-процесс** — уровень имперсонации. **Выбран.**
   - Один статический Go-бинарник на платформу, поднимается как локальный HTTP-сервис
     (Unix-сокет / named pipe на Windows), управляется по JSON: профиль клиента
     (`chrome_131`, `safari_18`…), прокси, cookie-jar, порядок заголовков, HTTP/2
     SETTINGS-фингерпринт.
   - Даёт не только JA3, но и HTTP/2 fingerprint — а именно на нём ловится половина
     наивных обходов.
   - Кросс-платформенно (важно: рабочая машина — Windows), не требует нативной сборки в npm.
   - **Отвергнуто `curl-impersonate`:** выше точность JA3, но нужен пер-платформенный
     билд, драйвится через CLI/FFI, cookie-jar и стрим SSE через него неудобны,
     Windows-сборки исторически хрупкие.
   - **Отвергнут `node:tls` со своим ciphers-порядком:** JA3 подделать можно частично,
     расширения TLS и GREASE — нет.
   - Слой опциональный: без бинарника gateway стартует, каналы с `fingerprint.impersonate`
     помечаются `unavailable` с внятной причиной, остальное работает.
3. **Playwright (persistent context)** — уровень `web-browser`, ступень деградации §6.3.
   Отдельный опциональный docker-слой и опциональная зависимость.

Все три реализуют один интерфейс; адаптер не знает, каким уровнем исполняется запрос —
уровень выбирает канал и эскалирует детектор челленджей.

### Валидация и схемы
**Zod 4** — источник истины и для входящих API-диалектов, и для `provider.yaml`.
`provider.yaml` парсится `yaml` → валидируется Zod-схемой → из той же схемы генерируется
JSON Schema для редактора (`provider.schema.json`), чтобы правки деклараций шли с
автодополнением в IDE. Это прямо работает на MTTR (§9).

### Персистентность
Интерфейс `Repository` + три реализации, выбор по конфигу:
- `file` (по умолчанию, zero-setup): JSON/JSONL в `~/.omniproxy` — сохраняет свойство
  «скачал и запустил», которое есть у текущего проекта и которое нельзя терять;
- `sqlite`: drizzle + `better-sqlite3` (нативный, но prebuilt-колёса есть под Windows/Linux);
- `postgres`: drizzle, для мультиарендного развёртывания.
Отвергнуто `node:sqlite`: в Node 22 экспериментальный, drizzle-драйвера нет.

### Очередь задач
In-process воркер + durable-стейт в выбранном Repository (job survives restart — §10).
BullMQ/Redis — опциональный драйвер за тем же интерфейсом `JobQueue`. Для одиночного
пользователя Redis не нужен и не будет требоваться.

### Хранилище медиа
Интерфейс `MediaStore`: `fs` (по умолчанию, дедупликация по sha256, TTL+GC) и `s3`
(опциональная зависимость `@aws-sdk/client-s3`, подключается только при выборе драйвера).
ffmpeg — внешний бинарник, обнаруживается, отсутствие = отключённый транскодинг, не ошибка.

### Наблюдаемость
`pino` (структурные логи, redaction секретов на уровне сериализатора — требование §12.7
исполняется механически, а не дисциплиной), `prom-client` (`/metrics`), OpenTelemetry SDK —
опциональная зависимость, включается флагом.

### Тесты
`vitest` (unit + contract на фикстурах), `@playwright/test` — только для browser-канальных
адаптеров. Контракт-тесты клиентских SDK (`openai`, `@anthropic-ai/sdk`, `@google/genai`) —
devDependencies, гоняются против поднятого gateway (§5).

### Криптография
`node:crypto` (AES-256-GCM для credential-store, scrypt для деривации мастер-ключа,
`timingSafeEqual` для API-ключей — уже используется в `server.js:90`). Внешних крипто-зависимостей нет.

## Итоговый список прод-зависимостей ядра
`fastify`, `zod`, `yaml`, `undici`, `pino`, `prom-client`, `better-sqlite3`+`drizzle-orm`
(только при sqlite-драйвере). Всё остальное — опционально и за интерфейсом.
Это осознанный отход от zero-dependency-догмы (§1.4) в пределах, которые можно назвать
поимённо и защитить.

## Последствия
- Базовый образ остаётся лёгким; `tls-client` и Playwright — отдельные слои (§10).
- Любой опциональный слой обязан деградировать в понятную ошибку, а не в креш при старте.
- Каждая новая зависимость — отдельный ADR. Порог: «а есть ли это в node:*».

## Поправка от 2026-08-27 (PR-0)

Для библиотечных пакетов (`schema` и далее) сборка делается штатным `tsc`, а не `tsup`:
typescript уже есть в devDependencies, а бандлинг библиотеке внутри монорепо не нужен.
`tsup` остаётся для приложений (`apps/gateway`, `apps/cli`), где сборка одного файла
действительно упрощает раздачу. Это уменьшает число зависимостей на старте — ровно то,
чего требует порог «а есть ли это в node:*».

Там же зафиксировано: у Turborepo по умолчанию включена анонимная телеметрия. Это
противоречит Х-5 хартии хакабельности, поэтому она выключена локально
(`turbo telemetry disable`) и заглушена в CI переменными `TURBO_TELEMETRY_DISABLED`
и `DO_NOT_TRACK`. Правило на будущее: любая новая зависимость проверяется на предмет
исходящих соединений, и если они есть — гасятся в том же PR.
