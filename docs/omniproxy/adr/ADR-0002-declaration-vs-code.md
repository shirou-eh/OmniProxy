# ADR-0002 — Граница «декларация против кода»

- Статус: proposed
- Дата: 2026-08-27
- Контекст: §4 требует «сначала декларация, потом код» и целевые ≥60% провайдеров
  без единой строки TS. Нужно определить границу так, чтобы она была проверяемой,
  а не декларативным пожеланием.

## Проблема с бинарной границей
Двухуровневая модель («либо YAML, либо класс на TypeScript») ломается на самом частом
случае web-API: запрос почти целиком статичен, но одно поле вычисляется —
HMAC-подпись тела, nonce, timestamp, PoW-ответ, base64 от JSON с полями из челленджа
(ровно случай DeepSeek: `server.js:591-597`). При бинарной границе такой провайдер
целиком уезжает в код, и вместе с ним туда уезжают авторизация, маппинг стрима и
capability — то есть всё то, что чинится правкой YAML за минуты. MTTR растёт на порядок
из-за одного поля.

## Решение: три уровня, а не два

### Уровень 1 — чистая декларация
`provider.yaml` выражает: URL и метод, шаблоны заголовков и тела с подстановкой
`{{...}}` из фиксированного контекста, извлечение значений подмножеством JSONPath,
framing потока (`sse | ndjson | json-patch | jsonl-poll | websocket`), маппинг
статусов и тел ошибок в типизированные ошибки, ретраи, capability, `probe`.
Целевые классы: B, F (большинство), часть A.

### Уровень 2 — зарегистрированные трансформы (`transforms`)
YAML **ссылается по имени** на функцию из белого списка, реализованную и юнит-тестированную
в `packages/engine-declarative/src/transforms/`. Вызов декларируется данными:

```yaml
vars:
  powHeader:
    transform: deepseek-pow-v0          # имя из реестра
    with: { targetPath: /api/v0/chat/completion, wasmUrl: "{{auth.wasmUrl}}" }
```

Реестр стартового набора: `hmac-sha256`, `sha256`, `md5`, `base64`, `base64url`,
`json-stringify`, `uuid-v4`, `nanoid`, `unix-ms`, `unix-s`, `random-hex`,
`url-encode-form`, `deepseek-pow-v0`, `jwt-decode-claim`.
Реестр расширяется кодом — но расширение переиспользуется всеми провайдерами.

**Явно отвергнуто: исполнение произвольных JS-выражений из YAML** (`eval`, `vm`,
jsonata-подобные движки с доступом к хосту). Причины: (а) декларации — это данные,
которые пользователь может прислать в issue или сгенерировать из HAR; исполнять их
как код означает RCE через захват; (б) выражения в конфиге невозможно юнит-тестировать
и невозможно отревьюить; (в) они мгновенно превращают YAML в плохо написанный язык
программирования. Граница жёсткая: **в декларации только имена и данные, никогда — код.**

### Уровень 3 — код-адаптер
Класс, реализующий `ProviderAdapter` (§4.3). Обязателен, когда:
- полезная нагрузка не JSON и не форма: вложенные строковые массивы Google
  `batchexecute`, protobuf, кастомный бинарный кадр;
- поток — конечный автомат с клиентским состоянием (WebSocket с квитированием,
  переподключением и переигрыванием, как у Perplexity);
- многошаговая логика с ветвлением, зависящим от содержимого ответа
  (загрузка файла: negotiate → presign → PUT чанками → commit → ждать индексацию);
- требуется реверс JS-бандла провайдера в рантайме (динамические ключи подписи).

**Ограничение уровня 3:** код-адаптер переопределяет **только `flow`**. `auth`,
`models`, `capability`, `probe`, `fingerprint`, `errors` он обязан брать из той же
декларации. Провайдера без `provider.yaml` не существует в реестре — реестр читает
YAML, а не сканирует классы.

## Как проверяется соблюдение
1. Линт-правило `no-provider-conditionals`: любое сравнение с литералом-идентификатором
   провайдера в `packages/core/**` — ошибка сборки (§12.3).
2. Тест `core-has-no-provider-imports`: граф импортов `packages/core` не содержит
   `packages/providers/*`.
3. Метрика `declarationCoverage` считается автоматически по реестру
   (`провайдеры без файла adapter.ts / все провайдеры`) и публикуется в
   `docs/providers/README.md` и в `/v1/capabilities`. Если она падает ниже 50% —
   это сигнал, что уровень 2 недостаточно богат, и надо расширять реестр трансформов,
   а не писать очередной класс.
4. Каждый код-адаптер обязан в `docs/providers/<id>.md` содержать раздел
   «почему не декларация» с конкретной причиной из списка выше. Причины «так быстрее»
   не существует.

## Последствия
- Правка сломавшегося провайдера в 80% случаев = правка JSONPath в YAML, без пересборки.
- Генератор из захвата (§8.3) целится в уровень 1 и подсказывает места для уровня 2;
  до уровня 3 он не поднимается никогда — там нужен человек.
- Цель ≥60% переформулируется честно: **≥60% провайдеров без `adapter.ts`**, при этом
  использование уровня 2 не считается кодом. По классам C/D цель заведомо недостижима,
  и это отражено в матрице поддержки, а не замаскировано.
