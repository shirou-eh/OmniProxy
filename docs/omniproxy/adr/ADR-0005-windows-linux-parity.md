# ADR-0005 — Паритет Windows и Linux с первого дня

- Статус: accepted (решение заказчика, 2026-08-27)
- Контекст: ответ на вопрос 3 — обе системы поддерживаются одновременно и полноценно,
  а не «основная Linux, Windows как-нибудь».

## Почему это решение, а не пожелание

Кроссплатформенность не добавляется в конце. Она либо соблюдается в каждом PR, либо
не существует: к моменту, когда кто-то впервые запустит проект на Windows, там будет
двести мест с `/tmp`, `pkill` и `chmod 600`. Прецедент уже есть в текущей кодовой базе:
`scripts/deepseek_chrome_auth.js:51` — `killExistingTestingChrome()` вызывает
`/usr/bin/pkill` и работает только на macOS, на остальных платформах молча ничего не
делает. Это не баг автора, это закономерность.

## Правила, обязательные к соблюдению

### 1. CI — матрица, а не галочка
Каждый PR гоняется на `ubuntu-latest` **и** `windows-latest`, полный набор тестов на
обеих. Красный Windows = красный PR. Дополнительно раз в сутки — прогон на обеих
платформах со свежим `pnpm i` (ловит расхождения в prebuilt-зависимостях).

### 2. Никаких POSIX-only вызовов
Запрещены: `pkill`, `ps`, `which`, `chmod`, `rm -rf`, `/tmp`, `/dev/null`, `$HOME`,
двоеточие как разделитель путей, обратные кавычки в шелле. Всё это — через `node:*`:
`os.tmpdir()`, `os.homedir()`, `path.delimiter`, `path.join`, `fs.rm({recursive:true})`,
`process.kill(pid)` по сохранённому PID вместо поиска по имени.
Линт-правило с чёрным списком строк ловит такие вызовы на этапе сборки.

### 3. Пути и файловая система
- Только `path.join` / `path.resolve`, никакой конкатенации со слэшем.
- `$OMNIPROXY_PROVIDER_PATH` разделяется `path.delimiter` (`;` на Windows, `:` на Linux).
- Идентификаторы провайдеров нормализуются в нижний регистр: NTFS регистронезависима,
  ext4 — нет; иначе модуль `MyService` на Windows затрёт `myservice`, а на Linux нет.
  Валидатор запрещает заглавные буквы в `id`.
- Хранилище артефактов шардируется по хешу (`ab/cd/abcdef...`), чтобы не упереться в
  260-символьный лимит пути Windows и не сложить сто тысяч файлов в один каталог.
- Атомарная запись — temp + `rename`. На Windows `rename` падает, если целевой файл
  открыт другим процессом: обязателен ретрай с backoff, иначе многопроцессный режим
  из ADR-0004 будет случайно ломаться только на Windows.
- Собственных симлинков не создаём: на Windows это требует прав администратора или
  режима разработчика. (pnpm внутри `node_modules` использует junction — это его дело.)

### 4. Права на секреты
`chmod 600` на Windows — no-op. Поэтому **защита секретов не может опираться на права
файловой системы**: основной механизм — шифрование AES-256-GCM с ключом из
`OMNIPROXY_MASTER_KEY` (или DPAPI/keychain, когда доступны). Права файлов ставятся
дополнительно и по возможности: `chmod` на POSIX, `icacls` с наследованием, снятым в
пользу текущего пользователя, на Windows. Отсутствие возможности выставить права —
предупреждение в `doctor`, а не отказ работать.

### 5. Межпроцессное взаимодействие
Sidecar TLS-имперсонации и воркеры общаются через абстракцию `LocalEndpoint`:
Unix-сокет на Linux/macOS, named pipe (`\\.\pipe\omniproxy-*`) на Windows.
Порт на localhost — запасной вариант для случаев, когда именованный канал недоступен;
тогда обязателен токен в заголовке, потому что localhost-порт на многопользовательской
машине доступен другим пользователям.

### 6. Завершение процесса
На Windows нет `SIGTERM` в POSIX-смысле. Graceful shutdown слушает `SIGINT`, `SIGTERM`
(где есть), `SIGHUP`, событие `message: 'shutdown'` от родителя и Windows-специфичные
`SIGBREAK`. Дренаж in-flight запросов, сохранение job-состояний и снятие аренды
аккаунтов обязаны отработать на обеих платформах — тест проверяет и там, и там.

### 7. Браузеры и внешние бинарники
Поиск Chrome/Chromium — по списку кандидатов на платформу плюс `CHROME_PATH`.
Playwright сам ставит совместимые сборки — это ещё один аргумент за него в качестве
ступени `web-browser`. Sidecar-бинарник качается под текущую платформу и архитектуру
с проверкой контрольной суммы; отсутствие бинарника — деградация канала, а не падение.

### 8. Строки и кодировки
LF в репозитории и в рабочей копии на обеих платформах (`.gitattributes`, уже добавлен).
Вывод CLI — UTF-8 с явной установкой кодовой страницы на Windows, иначе кириллица в
сообщениях об ошибках превращается в кашу — а сообщения об ошибках у нас несут
инструкцию для человека (И-2 хартии надёжности).

### 9. Контейнеры
Базовый образ — Linux (rootless Podman, наследуем текущий `Containerfile`).
Windows-пользователь получает нативный запуск через Node и, опционально, тот же образ
в Docker Desktop/WSL2. Отдельного Windows-контейнера не делаем — это дорого и никому
не нужно; нативный запуск на Windows обязан быть полноценным и без WSL.

## Известные шероховатости, которые принимаем

- **OneDrive.** Текущее рабочее дерево лежит в `OneDrive\Desktop`. Синхронизация
  `node_modules` с junction-ссылками pnpm — источник трудновоспроизводимых поломок.
  `doctor` будет это обнаруживать и предупреждать, но чинить за пользователя не станет:
  это его каталог и его выбор (см. хартию «пользователь — закон»).
- **Антивирус Windows** заметно замедляет `pnpm i` и запуск Playwright. Документируем
  рекомендацию по исключениям, не более.
- **Длинные пути.** `git config core.longpaths true` и рекомендация включить поддержку
  длинных путей в системе — в `doctor` и в README.
